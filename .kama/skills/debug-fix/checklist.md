# Debug Fix Checklist

## 安全边界

- 不执行删除仓库、覆盖用户改动、修改 Git 历史等破坏性操作。
- 不读取或输出 `.env`、密钥、令牌及其他敏感信息。
- 未经明确授权，不安装系统依赖，不修改全局环境。
- 默认不修改既有测试来迎合实现；如果测试预期本身错误，单独说明证据。

## 复现要求

- 记录原始失败命令、退出码和关键错误信息。
- 优先构造最小且确定性的复现，避免依赖随机等待。
- 异步问题优先使用事件、Future 或可控时钟验证，不用无依据的长时间 sleep。

## 修复要求

- 修改必须直接对应已证实的根因。
- 涉及重试、超时或取消时，验证资源清理和最终状态。
- 涉及工具调用历史时，验证 `tool_use` 与 `tool_result` 仍然配对。
- 涉及持久化时，至少验证成功路径和写入失败后的旧数据保留。

## 验收顺序

1. 最小复现用例通过。
2. 相关模块测试通过。
3. 没有引入新的告警、挂起任务或临时文件。
4. 汇报中给出执行过的确切命令和结果，不把“预计通过”写成“已经通过”。
